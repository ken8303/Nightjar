# Nightjar feature status

Source inventory updated 20 October 2026; see the dated reference-site review below. Nightjar is a beta; this is a scope inventory, not a claim of production readiness or full feature parity. A single completion percentage would hide the difference between implemented features, missing features and device acceptance.

Catalogue update, 27 October 2026: the planner now includes 30 additional NGC/IC objects with saved-list, diary, backup, comparison, calendar and offline support. Camera discovery retains its original Messier scope. See [data provenance](./data/README.md).

Current display policy, 24 October 2026: observing information is shown only with the geometric Sun centre strictly below −18°. Bright-time views offer a bounded next-darkness preview; eligible timeline samples and event shortcuts are filtered without moving actual astronomical event times. Tonight, summary snapshots and printable checklists include remaining full darkness and its calculated endpoint. Golden/blue-hour information is hidden. Keyboard-control design and further photo-feature development remain paused; the capability inventory below records the underlying features, with this display policy applied.

Offline planning update: the saved-data fallback can calculate full darkness at a chosen saved site for the saved time, current device time or an entered UTC time without network access. It can also calculate supported saved-target positions and the best 15-minute sample for supported saved targets over the next 24 hours at a checked fully dark time; the full planner still cannot restart offline.

Diary search covers names and listed cross-references across the curated deep-sky catalogue in the full planner. The offline recovery page also searches these catalogue names and cross-references within its saved-observation snapshot.

For exact test/build evidence and remaining release checks, use [BETA-HANDOFF.md](./BETA-HANDOFF.md) and [RELEASE-CHECKLIST.md](./RELEASE-CHECKLIST.md). Those records distinguish local work from the last successful GitHub validation and an actual Cloudflare deployment.

## Next work and acceptance criteria

User priority, 19 October 2026: pause photo recognition and further photo-feature development until the other work is finished. Existing reference images, camera thumbnails and Photo tools remain available; this pause does not remove them. Fix a confirmed regression in an existing photo flow if necessary, but do not expand its scope.

1. **Close the existing release gates first.** On real iPhone/Android hardware, verify known-object camera alignment, a slow full turn, portrait/landscape, interruption and return, plus explicit stop/restart behavior. On an installed PWA, verify update with an unfinished edit, offline recovery and backup/recovery downloads. Run the final-origin checks after the user's next batch push. Record device/browser/build and actual results; leave unavailable checks pending.
2. **Validate and extend the new light-pollution map.** The 2025 Lorenz visual layer is implemented with explicit opt-in, legend, provenance, coverage and missing-tile recovery. [LIGHT-POLLUTION-DATA.md](./LIGHT-POLLUTION-DATA.md) records live response evidence and its narrower scope. Physical touch/installed-PWA and final-origin use remain pending. Numeric sampling now has a provider-popup reference, signed-delta/grid-boundary tests and bounded cancel/retry handling. London plus Sydney, Atacama and Reykjavík popup/binary references now pass; this is not global model validation. Physical-browser acceptance remains pending; do not infer a Bortle class from a colour or describe annual data as live.
3. **Add satellites only with time-aware orbital data.** The proposed first slice and source/cache gates are in [SATELLITE-TRACKING.md](./SATELLITE-TRACKING.md); a shared ISS cache and selected-time direction panel are implemented locally. A bounded pass search, peak lighting and modelled sunlit/twilight/altitude intervals are implemented; separate hourly cloud context is available, while brightness/weather screening and atlas/camera tracking are still absent. Preserve the established source, propagation, epoch/staleness and selected-time contracts. Verify known reference positions, below-horizon filtering, stale/unavailable feeds and foreground recovery. Do not imply visibility from geometric position alone.
4. **Scope further forecast/Moon expansions separately.** Seeing/transparency needs a provider and clear definitions; alerts need permission/delivery/lifecycle design; lunar shadow simulation needs its own model and validation. Existing nearby tools should not be relabelled to imply these capabilities.

Photo recognition, wider-field framing and other new photo capabilities are deferred by the user. Revisit their solver/index, memory, privacy and accuracy requirements only when that work is resumed. Existing atlas-framing device acceptance remains part of regression testing, without new photo features.

This order follows the user's current priority. A concrete bug found in an existing flow takes precedence over adding another feature.
