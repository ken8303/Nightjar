# Nightjar

A responsive stargazing planner built with React, TypeScript, Vinext and Astronomy Engine.

## Included in this beta

- Live hourly Open-Meteo weather, an explained planning score, and a best-hour recommendation.
- Mobile Explore navigation uses a sticky section bar, with anchor clearance and keyboard focus return. Red-light guidance and save errors appear above observing controls; preference changes synchronize across planner tabs. A saved red-light setting applies to the loading screen before the interactive planner starts; unavailable preference storage does not block startup.
- Low/middle/high cloud cover, near-surface visibility, dew point and temperature margin for the selected forecast hour. Dew guidance is a heuristic; visibility is not astronomical seeing or transparency.
- Location search with validated unique results, distinct unavailable/empty feedback and a direct clear action, mobile decimal coordinate entry with N/S and E/W controls, optional browser geolocation, an OpenStreetMap view, and device-local saved places. Unreadable selected-site data is preserved with an explicit fallback and Retry guidance. Rename a selected site with a readable name; saved sites retain their coordinates, time zone and sky rating. Unreadable saved-place collections show Retry guidance and keep their stored data and last readable sites.

It is annual modelled zenith brightness, not a Bortle class, live forecast or numeric point measurement. Online map tiles are requested only after opening the map; no offline map download is offered.
- Shared observing time in UTC with local-time display; bright-star sky chart and calculated planetary positions. On first open, the time starts at the next astronomical-dark period for the restored site, or evening civil twilight when full darkness is unavailable in the next two days. If neither occurs, it starts at the next hour.
- Search the 42 existing sky targets by name, including Unicode-compatible and spaced text. Filter by horizon visibility or a strict altitude above 30°, inspect altitude/azimuth, and highlight a target in the atlas.
- Twelve-hour Moon/planet altitude table: only objects with a sample above 30° are shown, ordered by peak altitude. Peak-hour jumps, daylight context and above-30° shortcuts after civil twilight share target selection with the atlas. Mobile controls browse the same order; chart/details links preserve the selected object and time.
- Moon phase, illumination and horizon position; next Sun/Moon rise/set and astronomical darkness crossings.
- Latest NOAA OVATION aurora outlook, hemisphere grid, local model estimate, timestamps, stale-data warnings and separate cloud context at the actual fully dark NOAA forecast time.
- Typical annual meteor peak windows with calculated Moon illumination and downloadable all-day calendar events. Recommendations include only complete hours remaining after the selected time, and move to the next annual occurrence when the site-local window has ended. Occurrences beyond supported UTC years 1–9999 are omitted with a boundary notice.
- Golden-hour and blue-hour windows for morning/evening, based on Sun altitude and the shared observing time. The Milky Way direction marker uses galactic longitude/latitude zero in a defined J2000 frame, transformed to the observing date; it marks a regional sightline.
- Camera field-of-view, 35 mm equivalent focal length, image scale and guiding RMS conversion.
- Named equipment setups saved on this device. Unreadable collections show Retry guidance, preserve stored data and retain the last readable setups and current imaging fields.
- Small-field mosaic planner with overlap, rotated panel centres and CSV export. Enlarge framing guide provides readable numbered panels, 100–300% zoom, keyboard shortcuts and scrolling on compact screens.
- Imaging inputs accept a dot or a single decimal comma, signed values and scientific notation. Omit thousands separators. Raw incomplete/invalid text is retained separately from calculations and saved-equipment validation; malformed values cannot enable setup saving or mosaic export. Positive fields use decimal/numeric keyboard hints, and signed fields keep a keyboard with minus entry available.
- Interactive 3D Moon with NASA surface imagery, phase lighting and a lunar phase timeline. Portrait framing keeps the reset globe inside the narrow viewer; labels avoid overlap and prioritise the selected landmark. Focus the globe for arrow-key orbit/tilt, +/− zoom and Home near-side reset; the controls and landmark list remain available. Select a list name and use Centre to restore an offscreen landmark, even with labels hidden.
- Compare up to four saved/current locations at the same UTC forecast hour, with weather, Moon visibility and an explained planning score. Previous successful forecasts remain visible during refresh/failure with explicit update status; highest-score labels require fresh results for every selected site. Each site also shows its best remaining dark forecast window and can open the Tonight planner at that site and time.
- Upcoming lunar eclipses with global contact times and local Moon altitude at each contact, plus UTC-safe calendar downloads containing the full event and contact notes.
- A feature-detected WebMCP location tool. Coordinate-only selections preserve known time zone, country and Bortle metadata for matching sites; explicitly supplied values win.

Camera discovery offers 42 star/solar-system targets, 109 Messier targets or 151 combined; the default stays stars/solar system. Fullscreen target actions include manual direction preview with camera/motion off and a direct live-time photo/details handoff. Mercury, Uranus and Neptune have attributed NASA reference photos; solar-system magnitudes follow the selected date. ## Run locally

Requires Node 22.13 or newer.

The observing-time controls step backward or forward by one elapsed hour, including across clock changes. **Next darkness** uses the selected time and site to find full astronomical darkness within 48 hours; if none occurs, it keeps your time and explains why. The hourly forecast and deep-sky altitude timeline support Left/Right and Home/End browsing without changing the observing time; Enter or Space selects a sample. Ctrl, Alt and Command shortcuts retain their normal behavior. Short-screen forecast cards use compact spacing so keyboard-focused hours remain readable below mobile navigation. **Plan best hour** selects a fresh recommendation, while **Use closest forecast hour** recovers from dates outside the available forecast, missing hours or unavailable cloud estimates. It chooses the nearest full-darkness hour with known cloud cover, skipping bright times and unknown estimates; if none exists, no recovery time is offered. Time shortcuts preserve the existing unfinished-edit confirmation. Forecast reconnect recovery records whether the last request started online: an offline attempt cannot satisfy a later detected reconnection, while a manual retry started after returning online prevents duplicate acquisition.

Local time entry displays the selected UTC offset, including which occurrence of a repeated autumn hour is selected. Nonexistent spring times retain the previous instant until corrected or cancelled.

**Download summary** saves a text snapshot of the selected site, exact observing time, Sun/Moon conditions and weather currently shown. Its filename includes the site and exact UTC observing time so same-day plans are easier to identify in Files; the full site name stays in the document. It includes low/mid/high cloud cover, dew point and near-surface visibility when available, alongside forecast timestamps and unavailable, stale or failed-refresh warnings. It makes no extra provider request and does not update after download. **Share summary** appears when the device offers native sharing. It sends the same text snapshot to the device’s share options after you tap; cancellation leaves the planner unchanged, and sharing failures keep Download summary available. Completion identifies the original shared site/time even if the planner changes while sharing is pending. Saved-target checklists and data backups remain available separately in Sky atlas and My places.

Seven-night windows show their own weather timestamp, refresh status and retry action. A touch-sized Use suggested window action selects the highest-scoring available nightly window, preferring longer windows and then earlier starts for equal scores. It is offered only with a known, fresh, successful forecast and a positive score; refresh, failed refresh, stale/clock-uncertain weather or unavailable windows withhold it. Unfinished time edits use the existing review before selection. Each suggestion tap rechecks the exact current time and forecast freshness. A window that has started or a forecast that has expired keeps the observing time unchanged and shows recovery guidance. Their calendar files retain the weather fetch time and any pending, failed-refresh, stale or clock warnings. Files are fixed snapshots; refresh and export again for updated conditions.

Site comparison offers a direct planning action when one selected site has the highest same-hour score and every selected site has a fresh, successful forecast. The recommended-site action rechecks every compared forecast at the exact tap time; an expired peer or uncertain clock keeps the current site/time and offers refresh guidance. Ties are identified without choosing a site automatically. Pending, failed, stale, missing or clock-uncertain forecasts withhold the recommendation; the site cards still show their available data and status. Planning a site/window, choosing a saved or searched site, using valid coordinates, and View conditions reveal Tonight and focus its heading after any required edit review. Removing a comparison card returns focus to its site checkbox, or to the comparison heading if that control is unavailable. These handoffs leave a newer active editor alone.

Both target finders can filter to saved catalogue targets while retaining their existing search and visibility filters. Filtering keeps the selected object and its notes; a notice explains when its details are outside the results. Unreadable saved lists keep any results already read in that view with explicit recovery guidance; an unreadable list on return stays unavailable and does not claim zero target results. If a peer update removes a focused catalogue result, focus returns to that finder’s search without claiming a newer active editor.

Bright-target details offer Back to bright-target browsing, retaining the selected object, notes and filters. Clearing a selected bright target returns to the browsing controls without focusing a text field. Search and visibility filters, unfinished time edits and saved or unsaved target notes are retained. The clear icon has a 44 px hit area on tablet and desktop layouts as well as phones.

Deep-sky results provide touch-sized actions to view the selected object's details or open the observing diary. These remain available when the selection is outside the current filters. Jumping within the page keeps unfinished time fields, per-object drafts and any existing diary edit; it does not change the selected site or instant. Details and diary also offer Back to deep-sky browsing, which returns to the retained filters without focusing a text field. Diary fields use 16 px text on touch devices, including iPad layouts.

The observing diary also offers a way to widen an empty object scope while preserving its search and date filters. Diary counts distinguish loading, unavailable storage and a retained earlier read; they only describe an empty diary after a successful read. Reports and saved-entry changes stay paused while saved observations are unreadable. Explicit save attempts refresh the displayed saved list even when a conflicting edit or write failure prevents saving. Your unfinished text stays separate, so cancelling and reopening uses the latest saved observation. Cancelling a diary edit returns focus to its visible saved observation or the results heading. Peer removal of a focused diary row also recovers to that heading. Clearing an unfinished form focuses Undo; restoring it focuses the form or identifies the restored object when another object is selected. Failed form writes focus recovery guidance, and later editor focus takes priority.

Both target finders retain search/visibility filters, and the deep-sky explorer retains its selected object, when visiting another planner section. The planet visibility picker and its previous/next browsing choices also survive section navigation for the current visit. If a preferred object has no hourly sample above 30° in a new window, the panel identifies the highest-ranked fallback; the preference returns when available unless you explicitly choose another object. Browsing alone leaves the selected atlas target and time unchanged.

Deep-sky comparison also retains its expanded state, chosen objects and Moon-below-horizon filter, including an intentionally empty selection. Removed saved objects are excluded. Comparison, individual hourly and individual best-time actions apply the object and exact time together after any unfinished-time review; Keep editing leaves both unchanged. The individual altitude timeline marks its selected instant visually and with a pressed state. Successful planning reveals the selected object details, while peer removal of a focused comparison control falls back to its heading.

Planet-visibility peak and hourly actions use the same object/time guard: cancelling leaves the atlas selection and observing instant unchanged, and accepting reveals the selected target details while retaining target searches and notes. The diary also retains its search, date range, outcome and object scope across planner sections; unfinished invalid filters remain available for correction. Site comparison retains chosen sites, including an intentionally empty selection, while excluding sites that have been removed. This browsing state lasts for the current page visit, is excluded from backups and is cleared by reload. Clear filters resets the search while keeping the selected object and its notes.

## Data and limitations

Weather and place search are fetched server-side from Open-Meteo; no API key is configured. Review provider terms and capacity before commercial use. Saved places are browser-local and are not account-synced. Location coordinates are sent to the weather provider and map provider when those views are used.

Twilight classes, solar terms in the planning score, darkness windows and first-open timing use the geometric Sun centre, consistent with the darkness milestones and [USNO twilight definitions](https://aa.usno.navy.mil/faq/RST_defs). Object viewing positions still use normal atmospheric refraction; Moon-free hours use the apparent Moon centre relative to the ideal horizon.

The planning score is a transparent heuristic, not astronomical seeing or transparency. There is no terrain horizon correction. The star catalogue is a small bright-star selection with approximate J2000 source coordinates transformed to the observing date; this is not a navigation instrument. Meteor peaks are typical annual dates, not year-specific forecasts. The annual calendar links to IMO for detailed current bulletins.

Implemented locally: the optional 2025 light-pollution map and explicit numeric model readings, lunar libration with an Earth-facing globe view, and the current equipment/mosaic grid on the 2D and 3D atlas. Model readings are annual estimates rather than live sky measurements; see [LIGHT-POLLUTION-DATA.md](./LIGHT-POLLUTION-DATA.md).

An optional selected-time cloud comparison uses ECMWF IFS 0.25°, GFS and ICON global cloud-cover estimates through Open-Meteo, only while fully dark. It is separate from the main forecast and does not estimate astronomical seeing. An unavailable model remains unavailable; model run times are not shown.

Not implemented: multi-model comparison beyond cloud cover, automatic aurora alerts (the short-term outlook is included), automatic camera-lens calibration, the full NGC/IC catalogue, sky-photo recognition, cloud accounts and push notifications. Full planner startup when reopening offline is also unsupported; the offline fallback provides saved device data and on-demand full-darkness calculations for a chosen saved site using the saved observing time, the device clock or an entered UTC time. Keyboard-control and photo enhancements are paused at the user’s request.

For remaining release checks, see [Current completion checklist](./RELEASE-CHECKLIST.md#current-completion-checklist--22-october-2026).

- Phone navigation uses the Explore menu for every section; narrow desktop screens use a two-row tab grid. Controls use larger touch targets, 16px form text and safe-area padding; data tables scroll inside their own panel.

The fallback reads the last selected observing time, saved targets and full notes (including notes for targets removed from favourites), the last selected site and up to 100 saved places and imaging setups from this browser's local storage. It displays the time in the site's time zone and UTC, and can calculate saved-target positions and sampled opportunities for supported saved targets at a checked fully dark time. It does not update live forecasts offline. The service worker also keeps up to 80 previously fetched, same-origin `/_next/static/` app files for an open session across brief connection drops. - Browser installation and private-site sign-in should also be checked on a physical iPhone/Android device.

The offline page resamples its connection hint on foreground return and offers a manual refresh of saved details. A return notice says the snapshot may have changed; a storage event identifies a known change. Failed site/time preservation stays visible until an explicit retry succeeds. These notices leave saved data and displayed notes intact.

While the offline recovery module loads, Cancel preparing recovery copy keeps the page and stored data intact and returns focus to Download. Cancelled preparation cannot trigger a late download; try again explicitly when ready.

The offline page can prepare a separate raw recovery JSON copy, including malformed stored text and stored unfinished forms. The planner and offline page share its implementation and format. Installation caches its small JavaScript module with the offline page; both resources must validate before being cached. This copy is manual recovery, cannot be imported as a normal backup and does not include unsaved text held only in another view. Reads/rendered collections are bounded, oversized values show the saved-data warning, and copies report unreadable/excluded keys. Verify native file receipt before leaving.

Waiting PWA updates reload only after the user chooses Update and reload. If activation fails or takes more than 15 seconds of a usable foreground wait, the controls recover and offer an explicit reload action. Background/history suspension pauses this deadline; return starts a fresh wait. The selected observing time has a separate per-tab session copy, so an update or recovery reload cannot accidentally use another tab's time when session storage is available. Saved places, targets, notes, equipment and atlas preferences remain in local storage. Tests cover activation races, timeout/message failures, listener cleanup and per-tab time isolation. Local browser checks cover a real worker update with two different tab times, a deliberately stalled test worker, the mobile recovery controls and reload preserving the chosen time. Long-lived sessions request a service-worker update check every 15 minutes and when the page becomes visible, returns from browser history, or reconnects. Checks require both a visible page and an online browser, run at most once per minute and cannot overlap. Background failures stay quiet and can retry on a later event. These checks never activate a waiting worker or reload the planner. Tests cover event throttling, hidden/offline gating, pending requests, cleanup and retry after failure. Integrated local browser checks verified two explicit updates retaining millisecond observing time, saved notes/favourites and unfinished diary snapshots with Unicode text. Physical-phone resume/reconnect and installed-PWA testing remain outstanding.

## Saved data and recovery

- If saving bright-target notes fails, the text remains while Sky atlas is open and a Retry saving notes button is available. Leaving the tab or reloading may lose unsaved edits; retry can save them after storage becomes available. Camera preference failures likewise apply only while that viewer remains open.
- Saved places and equipment setups are limited to 100 each, matching backup validation. Existing entries can be updated at capacity. An addition or Undo that would exceed capacity shows a message without silently dropping records. Oversized legacy lists remain available for manual cleanup. Saved-place aliases at the same coordinates keep separate names and ratings; edits resolve a unique named entry, and ambiguous versions or conflicting alias renames are refused without overwriting them.
- Target notes include a manager for imported/older catalogue names, removal with Undo, and retained unsaved edits during storage failures or cross-tab updates. Saving enforces the same 100-note bound as backups; oversized legacy collections stay readable until you explicitly free space.
- Saved-place mutations reread the latest stored collection and reflect other-tab updates. Removing a changed record is refused. Failed saves leave the saved list unchanged; the selected observing site remains usable. Saved places offer Undo for the latest removal until another place is removed or the page reloads. Equipment mutations likewise reread the latest saved list, refuse changed-dimension removals and synchronize other-tab updates without replacing the imaging draft. Equipment Undo lasts while Photo tools is open. Both target lists reread the latest stored IDs before saving or Undo, preserving other-tab additions. Failed writes keep the saved list unchanged and retain Undo with nearby recovery guidance. Older imported bright-target names can be removed explicitly without deleting their notes. Both target lists offer Undo while Sky atlas is open. Recovery preserves a record already re-saved and keeps current settings, notes and diary records.
- Diary records and unfinished forms are separate. Drafts retain their original site/time until explicitly changed and are excluded from normal plan backups, offline listings and saved-observation reports/CSV. Failed saves retain text in the current view, with retry, conflict review and a separate manual form recovery download. Reviewed copies last until another review or leaving Sky atlas; unsaved text can be lost on leaving/reloading. Raw storage recovery copies include stored forms but cannot recover unsaved view-only text. Neither recovery format is directly importable as a plan backup. The app stores no cloud account data.
- Sky atlas shortcuts open camera discovery or jump to the chart, deep-sky explorer and diary. A deferred section can load for up to 15 seconds before retry guidance appears. Closing camera returns focus to its launch button; camera and motion access remain explicit actions inside the viewer.

Sky-rating conflicts appear beside the rating selector. When another view selects a different named version at the same coordinates, choose the intended site again before rating; sibling saved versions and their metadata are preserved.

Backup import reviews retain a snapshot of the saved plan. If that data changes before Import, the app updates its counts/conflicts and requires another explicit import action; an over-capacity merge clears the old review and identifies the collection limit. Error messages receive focus, and cancellation returns to file selection. Failed-import rollback restores only values still matching that import's writes, preserving newer peer values and reporting possible partial changes. Browser storage transactions remain non-atomic across keys/tabs.

## Deep-sky attribution

The 469-object planning catalogue combines the original 109 Messier records with a curated 360-object NGC/IC extension adapted from [OpenNGC by Mattia Verga and contributors](https://github.com/mattiaverga/OpenNGC), under [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). See [data provenance and regeneration](./data/README.md) for the pinned source revision and data licence. M102 has no source cross-reference. Full constellation labels follow [IAU names](https://iauarchive.eso.org/public/themes/constellations/), with the source's Serpens Caput/Cauda split retained. Magnitude filters use integrated visual magnitude and do not establish surface brightness or equipment visibility.

## Technical reference

[Development notes](./DEVELOPMENT-NOTES.md) retain detailed feature behaviour, calculations, attribution and earlier local QA evidence. Historical test counts there describe individual development batches; use the release checklist for current status and remaining acceptance tests.

Failed note and diary-form saves keep text in the current view. Section navigation warns before discarding it; PWA and failed-view reload controls pause until it is saved or copied. Native reload/close prompts remain browser dependent. Retried target notes that conflict with a newer saved version require an explicit version review, preserving unrelated notes and unfinished edits. Long reviewed versions support keyboard scrolling. Diary snapshots retain optional site country; search includes it, reports/offline cards show it and CSV appends a Country column.

Imaging fields retained during this visit now pause page-exit/update reload after a failed save. Photo tools provides a save retry and manual JSON recovery copy; moving between planner sections retains the draft. Imaging recovery files are separate from plan backups and exclude saved equipment profiles. Native phone recovery-file receipt remains to be checked.

Unfinished observing-time entries retain their draft across sections and pause reload/update and site changes until resolved or explicitly reviewed. Use Review time edit in the recovery notice to focus the draft; from Aurora it opens Tonight. Repeated local clock-change times require choosing their UTC occurrence. Cancelling keeps the previously selected instant.

Manual coordinate drafts stay available across planner tabs and block app reloads until used or cleared. The reload warning offers Review coordinates to reopen and focus the form. Signed pasted values and decimal commas are accepted; incomplete or invalid coordinates leave the selected site and time unchanged. Coordinate drafts are temporary and are not included in backups.

Reload warnings offer direct review of unfinished observing time, coordinates, imaging drafts, diary forms, target notes and site-name edits. Site-name review focuses the retained editable name. Target-note review opens note-management retry guidance without changing the selected object. Diary review focuses its retry/recovery controls; imaging review opens Photo tools. Coordinate review focuses the first incomplete field, and time review focuses the retained time entry.

Deep-sky details show catalogue J2000 coordinates in hour/minute/second and signed degree/minute/second forms. Copy J2000 coordinates includes those formatted values, the target identifier, epoch label and original decimal values. Clipboard failure leaves selectable values available. The display rounds formatted seconds to one decimal place; it does not change catalogue values or current sky calculations.

If camera video pauses while its track remains available, use Resume camera feed in ordinary or fullscreen controls. It retries playback without reacquiring the camera or clearing the followed object/alignment. A still-muted track needs to recover or the camera can be stopped and restarted. Late playback results cannot revive a closed or replaced viewer.

The full-screen camera picker includes discovery catalogue choice, object search and Clear search. On phones the catalogue chooser spans the panel width; scroll guidance remains visible when controls overflow. Switching catalogues keeps the followed object when it belongs to the new catalogue; otherwise the picker returns to Explore all objects. Its query is shared with Settings, preserves your followed object even outside the results, and does not filter discovery labels. Clear search returns focus to the active search field.

Camera sky positions refresh every 15 seconds while the viewer is visible. Backgrounding cancels that timer and returning refreshes immediately; camera, motion and screen-awake requests still require an explicit restart. Closing the viewer removes its clock and listeners.

Camera and 3D loading placeholders show recovery guidance after 15 seconds. Reload pauses for unfinished entries. Reviewing an edit closes the camera/3D overlay before focusing its planner field, so the dialog cannot trap focus behind the recovery action.

Long loading/error guidance in the expanded 3D dialog scrolls within its panel on short screens. The recovery panel can take keyboard focus and scroll with standard keys, keeping review and reload actions reachable.

Sky-section shortcuts explicitly focus their link while waiting for a deferred section, so pointer activation that leaves focus elsewhere does not silently drop the jump. Moving focus to another control before the section loads still cancels the earlier jump.

For the next physical-phone and hosted-release checks, see [BETA-HANDOFF.md](./BETA-HANDOFF.md).

A requested PWA update gets a fresh timeout window after returning from background or page suspension. If it genuinely times out, the recovery actions remain available; unfinished edits still block reloading. Native installed-app suspension and update timing need phone acceptance.

If target notes cannot save, Download unsaved notes prepares a manual JSON recovery file from edits held in the current view, including original versions and explicit removals. The copy may contain private text, cannot be imported as a plan backup, and does not mark edits as saved. Keep it before reloading; retry saving after restoring browser storage access.

Successful explicit target-note save retries return focus to the relevant note field or manager selector. Failed retries keep their recovery control, and automatic saves while typing do not move focus. Deferred handoffs leave a newer active editor alone.

Aurora requests within one active Worker instance share an in-flight NOAA fetch and retain the existing five-minute success cache. Failed reads are not cached and later requests can retry. Separate Worker instances keep separate caches; this is not a distributed request limit.

The offline darkness calculator is generated from the locked astronomy dependency with `npm run build:offline-darkness`; tests verify its bytes and agreement with the planner. It uses a chosen saved site and the explicitly chosen saved, current device or entered UTC time; during daylight it previews the next fully dark time within 48 hours and can check that time without changing the saved plan. At a checked fully dark time, supported saved deep-sky, bright-star and solar-system target positions can also be calculated offline. It is not a weather forecast.

The planner has an English / Traditional Chinese language selector. The chosen language is stored on this device and can be changed without changing the selected observing site, time or unfinished forms. Traditional Chinese currently covers navigation, the core mobile forecast, observing-time controls, location entry, the cloud-model comparison, parts of the Moon view, and deep-sky filters, timelines, Moon context and comparisons, the core observing-diary form and filters, and the planet-visibility planner; some detailed tools, recovery messages, exported files and the offline fallback remain in English. Deep-sky search accepts Traditional Chinese constellation names as well as catalogue identifiers and English names. The Open-Meteo place search may require English or romanized names even when Traditional Chinese is selected.
